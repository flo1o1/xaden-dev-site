## [Unreleased]

### Changed
- Headlines from level 3 down in the main content (`h3` to `h6`) are set in Inter instead of Cinzel; the page title and the section headlines (`h1`, `h2`) and everything outside the main content keep Cinzel.
- Security, "Before a release: a security review": the block holds only the command of the chosen assistant (`/xaden-security`, `$xaden-security` or `xaden prompt security-review`), so the copy button copies something that runs. The `prompt` shortcode prints just the command when label and text are empty.
- A docs page with `toc: top` in its front matter shows "On this page" only as the box above the text, on every screen width, without the right column; Troubleshooting uses it because its long list of entries fits the column badly.
- "On this page" highlights the entry of the section in view while you scroll (an optional script, `toc.js`; without JavaScript the entries are plain links; REQ-014).
- Project commands: `xaden project check` and `xaden project req` have their own entries there (moved from Work commands, which lose `check` and `req`); each names the shortcut `xaden check` or `xaden req`. The combined pointer entry is gone; `xaden check` and `xaden req` keep a one-line entry each, because `xaden help` lists them.
- The docs pages show "On this page" in its own column right of the text from the `xl` breakpoint (sticky), and as an open box above the text on narrower screens; the sidebar lists only the pages. Project commands now holds every `xaden project` command (`setup`, `doctor`, `fetch`, `pin`, `rules`, `ignore-list`, `persona`, `release`, `preset` moved there from Team and Work commands), with a short entry for `project check` and `project req`.
- Reference and Troubleshooting follow Xaden `main` after REQ-132: `xaden project check` and `xaden project req` are the commands and `xaden check`, `xaden req` and `xaden version` aliases, `aidd` is a namespace of its own with `xaden help aidd`, and the two messages for a missing project have Troubleshooting entries. The headings of `xaden check` and `xaden req` stay because the check against the pinned release (0.5) lists them.
- `inbox/` is git-ignored, as the site's `CLAUDE.md` already said: drafts and assets dropped there are never committed.
- Docs pages without headings no longer show an empty "On this page" block (for example Contributing).
- The "Docs" entry of the main menu opens Quick start instead of the Documentation overview; the submenu is unchanged and the overview stays at `/docs/`.
- The cards on the Documentation page no longer list the pages of their section; the card text and the Open button remain.
- Reference describes two changes of Xaden `main` (REQ-128, REQ-129): `xaden aidd enable` and `project pin` run the framework's CLI only after your yes, and `xaden project pin` writes the generated CI workflow beside an older one as `xaden.yml-dist`.
- Reference and pages follow Xaden `main` after the command namespaces (REQ-131): `xaden core upgrade` and `xaden core version`, `xaden project create|adopt|remove|pin|fetch|doctor|rules|preset|setup|release|persona|ignore-list`; the old top-level spellings are gone. Project commands explains the two namespaces and the limit for a project pinned to an older Xaden; Quick start, Troubleshooting, Security and Credits name the new spellings. Short entries for the old spellings stay at the end of Project commands, because the check against the pinned release (0.5) still lists those commands; delete them when the site pins a release with the namespaces.
- Reference follows Xaden `main` after the classic project was dropped (REQ-001, REQ-100): `xaden create --classic` and `xaden update` are no longer entries, Project commands lists `create` instead of the old `new`, and Security, Configuration and Check commands no longer compare with a classic project.
- Reference follows Xaden `main` after REQ-130 dropped its compatibility shims: `xaden update-check` and `xaden new` are no longer commands (the Reference keeps a one-line `update-check` entry until the site pins a release without it, because the release check lists every command of the pinned release), `xaden upgrade <version>` installs on the machine also inside a project (the project moves with `xaden pin`), and the sentence about the old meaning of `upgrade` is gone.
- Reference describes `xaden upgrade --check [--if-due]` of Xaden `main` (REQ-130): it also lists a project's outdated npm and pip dependencies, marks a major jump `(major)`, and `xaden update-check` is shown as deprecated. Configuration and Files and folders name the new command.
- Reference describes the lookup commands and the smaller index of Xaden `main` (REQ-126, REQ-127): `xaden req list --epic/--status`, `show --brief`, `for <path>...` with the optional `paths:` line of a requirement, `find <word>...`, the short `INDEX.md` and the full `INDEX-full.md`, the warning of `xaden check` about a `paths:` entry that matches nothing, and `xaden doc rules-<topic>` for the rule sections that moved out of the always-loaded rules file; Files and folders lists `INDEX-full.md`.
- `scripts/sync-docs.sh --main` always renders: a guide file of Xaden's `main` that `PAGES` does not list yet gets an entry derived from its path, a command in `xaden help` without a Reference entry and a link to an unknown page only warn, and a listed page whose source `main` removed is skipped. A release or CI build still fails on each (REQ-006).
- Reference describes `xaden aidd` (`enable`, `status`, `disable`, `pin`) and its three settings `aidd-cli`, `aidd-release` and `aidd-assistants`, and Files and folders lists `.aidd/`. The new Developer Guide page "Use the AIDD framework" has an entry in `scripts/sync-docs.sh` marked `unreleased`, which fixes `scripts/sync-docs.sh --main` failing on it (REQ-006); readers' pages drop a trailing "(REQ-nnn)" of the guides (REQ-002).
- The Contributing section lists "Xaden and the AI-Driven Development Manifesto", the page Xaden's `main` added to map the manifesto to its rules. Its entry in `scripts/sync-docs.sh` is marked `unreleased`, so `scripts/sync-docs.sh --main` renders again; it sits in Contributing because the page names rule IDs and repository paths, which the other guides must not (REQ-002, REQ-006).
- Reference and Troubleshooting describe the audit kinds of Xaden `main`: `audit` and `security` in `expect` and the check kinds table, the `NOT COVERED:` line, the presets that map `pip-audit`, `bandit` and `npm audit`, the scan finding `unittest` and Makefile or npm `audit` commands, and four Troubleshooting entries (REQ-105, REQ-106 of Xaden, plus the hook fix for an untracked `xaden/` folder).
- `scripts/sync-docs.sh --main` renders even when Xaden's `main` has a guide page that the pinned release lacks: a `PAGES` entry marked `unreleased` renders when its source exists and is skipped with a warning otherwise (REQ-006). `scripts/dev.sh` also finds the Xaden checkout from a worktree of the site.
- Reference and Troubleshooting describe the commit check fix on Xaden `main`: exit status `2` and the shallow-checkout failure of `xaden verify-commits --ci`, and that an adopted project's check starts after the adoption (REQ-109 of Xaden).
- Reference, Troubleshooting and Security describe the commit check in the adopted CI: the new `xaden verify-commits` entry, the `--commit-convention` option of `xaden adopt`, how the scan chooses `commit-convention`, and two Troubleshooting entries (REQ-107, REQ-108 of Xaden).
- Reference: `findings-status.<name>` is recorded by `xaden adopt` only for status 1, and `require-signature` refuses an empty value and git checkouts of Xaden.
- `scripts/dev.sh` renders the guides from the main of the Xaden checkout next to the site (`scripts/sync-docs.sh --main`), so the local preview shows what Xaden's `main` holds, including pages newer than the pinned release. Without that checkout it renders the pinned release as before.

## [0.5.0] - 2026-10-18

### Changed
- Quick start installs Xaden from the signed release zip (download, check the signature against the key on the About page, extract, `install.sh`); cloning stays described on the Install Xaden page for contributors. The docs describe Xaden v0.5.0.
- **Release cycle (REQ-023):** the site is published only from a version tag, no longer from every push to `main`. The site has the version of the Xaden release it describes (`VERSION`, replacing `XADEN_DOCS_VERSION`); `scripts/release-site.sh <X.Y.Z>` prepares the release commit, and `scripts/release-site.sh republish` a re-publish under the same Xaden release (`vX.Y.Z-0001`, `-0002`). CI publishes a tag only when it is the newest one, equals `VERSION` and is on `main`. The daily `bump-docs` workflow and the `DOCS_BUMP_TOKEN` secret are gone.
- The generated guide pages no longer end in a "Next" section; the previous and next buttons below the page already link there.
- Docs describe Xaden v0.4.0: the generated slash commands and skills carry the `xaden-` prefix (`/xaden-feature`, `$xaden-feature`, ...); the assistant picker shows them, and `scripts/sync-docs.sh` keeps turning the guides into picker blocks (REQ-022).

### Added
- Assistant picker (REQ-022): a list under the title of each docs page lets readers choose Claude Code, ChatGPT Codex, GitHub Copilot, Mistral Vibe or Other, and the commands on the page change to that tool's. Default and no-JavaScript view: Claude Code; Other shows the `xaden prompt` commands. The choice lives in `localStorage` and in a `#assistant=<name>` link. Quick start and the generated guides use it (`scripts/sync-docs.sh` rewrites the guide wording; it fails when that wording changes); the site check verifies every assistant has its commands.
- Prepare the site before a Xaden release is published: `XADEN_SOURCE=<checkout> scripts/sync-docs.sh` renders the tag named in `VERSION` from the checkout's git (REQ-006); the docs describe v0.3.0, with the new Check for updates page and the `xaden update-check` Reference entry.
- Reference: commands in three groups (project, work, team), the settings of `xaden/xaden.conf`, files and folders, exit codes and environment. The build fails when a command in `xaden help` has no entry.
- Troubleshooting: one page, grouped by area, symptom with cause and fix.
- Docs sidebar tree, previous and next links, and a stamp on every docs page with the Xaden release it describes (or "preview").
- Site check: every internal link and `#anchor` resolves.
- Requirement REQ-021: the site speaks plainly, with a light touch of the Empyrean world.
- `scripts/sync-docs.sh` renders Getting started, Security, Optional tools and Local LLM into the Admins, Developers and Security pages from the Xaden release in `VERSION` (pinned, v0.2.2); each page shows the version and release date; CI runs it before the build.
- Site content: Home (What, So what, Now what with real output of `new-project.sh`), docs landing page by task, About, imprint, privacy notice, a 404 page with links, and a footer with imprint, privacy and contact.
- Redesign: short home page (hero with a copyable one-line install, four benefit blocks, three steps), docs as one page each for Admins (prerequisites, install, optional tools, update), Developers and Security with a table of contents (`scripts/sync-docs.sh` splits Getting started into their sections), copy buttons on every code block, the logo in the header, favicon and hero, colors taken from the SVG logo, dark fantasy artwork with large overlapping dragon scales in the hero, on the logo side only, so text always sits on a plain background. `scripts/build-css.sh` builds the stylesheet.
- Docs menu with Quick start, Admins, Developers and Security; an install section for Admins (git clone or zip, per operating system); a hand-written Quick start page that uses the `xaden` command and explains every command below its code block; code blocks hold commands only (comments from the Xaden docs move into a list under the block); the "Edit on GitHub" links are gone; rule IDs, section references and repository paths are removed from the docs, and the site check fails if one comes back; the docs use the `xaden` command (new, update, setup, check, req, pack, release) instead of the `scripts/*.sh` paths, with the site check failing on a leftover script path.
- Developers page: "Bring an existing project" (merge its git history into a new Xaden project; steps run end to end). Security page rewritten as a high-level tour of how Xaden helps at five points of the workflow, with links to OWASP, gitleaks, semgrep and shellcheck instead of the full checklist.
- Deploy to GitHub Pages: after CI passes on a push to `main`, the site checked in that run is published by a separate job that alone holds the Pages permissions; `static/CNAME` names `xaden.dev`.
- Fix: the deploy dropped `/.well-known/security.txt` because the Pages upload action skips dot folders; hidden files are now included, and the deploy job fails if security.txt is not served afterwards.
- Security policy (`SECURITY.md`) and threat model (`docs/threat-model.md`) written for the launch, including the response headers GitHub Pages cannot set.
- Admins page: how to update Xaden itself (clone or zip). Xaden v0.2.3's new "Get Xaden" section is covered by the site's own Install section.
- Removed the unfilled user and admin guides (decision 0001); the README now describes how to build, check and publish the site.
- Project created from the Xaden scaffold.
- Hugo site skeleton with its own theme `themes/xaden` (dark, self-hosted fonts, one optional script for copy buttons), pages Home, Docs and About, a 404 page and `security.txt`; `scripts/check-site.sh` builds it and fails on other origins, inline script, a missing Content-Security-Policy or a `security.txt` that expires within 60 days; CI installs pinned, checksum-verified Hugo and Tailwind CSS CLI.

### Changed
- The documentation is restructured by kind of use. Docs menu: Quick start, Developer Guide, Admin Guide, Reference, Security, Troubleshooting. The two guides have one page per task (Developer Guide: create a project, add Xaden to a repository, check modes and baselines, kick off, build features, release, join a project, other assistants and local models; Admin Guide: requirements and platforms, install, update, pin one version per project, verify releases, optional tools and plugins, update a classic project, uninstall). Every page starts with the shortest path and ends with the special cases; headings say what the reader does.
- The guide pages are generated from one source file each in the Xaden release (`docs/guide/` and the shipped guides), not cut out of Getting started with patterns. `scripts/sync-docs.sh` lists the pages, resolves links between them, and fails on a guide file without a page. Releases before v0.2.4 have no `docs/guide/`, so `VERSION` must move to the release that has them before CI can render the site.
- Home page copy: a headline about AI code crossing the parapet and what Xaden checks on every step, benefit cards that state the means, four paths into the docs. `xaden create` replaces `xaden new` everywhere.
- Security, Quick start and the guide overviews are written on the site (`content/docs/`); `docs-parts/` is gone.

### Removed
- The install command and its note in the home page hero; the hero button "Quick start" leads to the install steps. REQ-018 is dropped, its remaining criteria moved to REQ-002.
- The Xaden scaffold: prompts, presets, personas, stack checks, requirements tooling, the pre-commit hook, the release script and the configuration of other AI tools. `scripts/check.sh` now runs shellcheck and gitleaks; `CLAUDE.md` holds the few rules that remain. The requirements and the threat model stay as plain files.
