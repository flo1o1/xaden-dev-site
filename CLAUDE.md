# CLAUDE.md — xaden-dev-site

Static Hugo site for https://xaden.dev. See `README.md` for build, check and publish.

- Work on a branch and open a pull request; never push to `main`. CI must pass before merge.
- Commits follow Conventional Commits (`feat`, `fix`, `docs`, `chore`, `ci`, ...); `scripts/verify-commits.sh` checks them in CI.
- What the site must do is in `docs/requirements/` (one file per requirement). Change it there first, then the code.
- Security of the site: `SECURITY.md`, `docs/threat-model.md`. Update the threat model when a change adds an entry point, a data type or an external service.
- The site sets no cookies, loads nothing from other origins, and uses no inline script (`scripts/check-site.sh` enforces it).
- The pages of the Developer Guide and the Admin Guide (`content/docs/developer-guide/`, `content/docs/admin-guide/`) are generated by `scripts/sync-docs.sh` from the guide files of the Xaden release in `XADEN_DOCS_VERSION`; edit the source in the Xaden repository or the script, not the generated pages. Quick start, Reference, Security and Troubleshooting are written here in `content/docs/`.
- To prepare the site before a Xaden release is published: tag it locally in the Xaden checkout, set `XADEN_DOCS_VERSION`, render with `XADEN_SOURCE=<checkout> scripts/sync-docs.sh`; the PR goes green only after the tag is on GitHub. Never push or create the tag yourself.
- Run `scripts/check.sh` and `scripts/check-site.sh` before declaring work done.
- Never read or commit `.env` files or secrets.

## Batch mode for small changes

Many small edits (copy, spacing, typos) go in one branch and one pull request. These steps are batched or skipped; everything above stays mandatory (branch and PR, CI green before merge, Conventional Commits, site security checks, no secrets).

- One branch and worktree per batch, one commit per item.
- While editing, run `scripts/dev.sh` (`hugo server` rebuilds on save). Run `scripts/check.sh` and `scripts/check-site.sh` once, before the push.
- A requirement is only needed when behaviour changes; copy and layout edits need none.
- One CHANGELOG entry and one COMPLETION REPORT per pull request.
- `scripts/sync-docs.sh` runs once per worktree; it needs the network.
- CI runs only on pull requests: open the PR, merge when `check` is green.
