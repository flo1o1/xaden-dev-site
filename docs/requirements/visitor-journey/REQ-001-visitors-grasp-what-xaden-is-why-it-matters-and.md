# Visitors grasp what Xaden is, why it matters and how to start within a minute

## Job

When I land on the home page from a link or a search, I want to see what Xaden is, what problem it solves and how to install it, so I can decide in about a minute whether to try it.

## Acceptance criteria

- Given the first screen, then the headline says what the site's user gets (AI-generated code that meets the team's quality bar), in plain words, and the lead names the three means: one rule book, checks on every commit, requirements every change answers to
- Given the first screen, then it shows the install command and one primary link to the Quick start, and names the supported systems (Linux, macOS) and the Windows status (WSL, untested), consistent with the documentation
- Given the home page, when read top to bottom, then the order follows the visitor's journey: the promise, four benefits, the steps from first command to release, then the paths into the documentation for a new project, an existing repository (both in the Developer Guide), installing and updating, and security
- Given any claim on the home page, then it links to the documentation section that backs it
- Given the home page, then no claim says that Xaden makes software secure or correct; it says what Xaden checks and records
